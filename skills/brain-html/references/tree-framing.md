# Brain 트리 화면 맞춤

2026-10-12 DVERSE `/brain`에서 확인한 상단 노드 잘림 수정이다. 선택한 축을 펼친 뒤 프로젝트·주제·도구를 누르면 고정 배율(0.8)로 확대하면서 상단 도구 노드가 일반 보기와 전체 화면에서 잘렸다.

## 구현 계약

- `lib/memory-core.ts`의 `CameraState.treeBounds`는 실제 트리 노드의 범위다. `viewport`는 표시 중인 SVG의 CSS 픽셀 크기다.
- `KnowledgeGraph`는 선택 트리에 속한 실제 force 노드 위치, 노드 반경, 코어의 전체 반경, 아래쪽 라벨 공간으로 범위를 구한다. 목표 레이아웃만 쓰면 물리 반발·드래그에 따른 이동을 놓칠 수 있다.
- `cameraRect`는 펼친 트리를 노드 선택보다 우선해 맞춘다. 기본 880×600 좌표 비율과 SVG letterboxing을 유지하고, 상단 72px(600px 미만 100px), 하단 88px, 좌우 72px의 여유를 확보한다. 컨트롤 배치가 달라지면 이 여백도 함께 조정한다.
- 노드 상세를 열어도 전체 트리의 범위를 유지한다. 코어·기억 상세 확대와 사용자가 직접 조작하는 pan/zoom은 유지한다. 축 이동·목록 선택 시 수동 카메라를 해제해 화면을 다시 맞춘다.
- callback ref로 실제 SVG DOM을 추적하고 그 요소를 `ResizeObserver`로 관찰한다. 전체 화면은 포털이 나중에 마운트될 수 있으므로 `[fullscreen]` 의존성만으로 관찰자를 연결하지 않는다. 교체·언마운트 시 관찰자와 휠 이벤트를 해제한다.
- SVG 자체의 최소 높이를 440px로 유지한다. 모바일에서 부모의 최소 높이만 지정하면 SVG가 가로세로 비율에 따른 약 240px 높이로 줄어들어, 컨트롤 여백을 제외한 트리가 지나치게 작아질 수 있다.
- 사용자 이력 데이터나 DVERSE 전용 상세 카드를 전역 스킬에 넣지 않는다. 이 수정은 독립 런타임의 일반적인 트리 동작이다. 추출 시점의 `source-manifest.json`과 MIT 고지는 보존한다.

## 검증과 배포

1. `node scripts/test-camera.mjs /path/to/project-with-node_modules`: 노드 선택 후 전체 범위 유지, 일반/전체/좁은 화면·이동한 노드의 여백, 코어 확대 회귀 검사.
2. `node scripts/build.mjs /path/to/project-with-node_modules`: 실행 번들·CSS 재빌드.
3. `render.py`로 새 임시 HTML을 생성한다. 기존 갤러리를 갱신할 때는 기존 JSON·제목·테마·샘플 표시를 보존하고 생성 결과를 확인한 뒤 교체한다.
4. `python3 scripts/verify.py`: 다섯 모드 생성·입력 격리·이스케이프·설치 무결성 검사.
5. 실제 브라우저에서 축 → 프로젝트/주제 → 맨 위 기술 노드를 선택한다. 일반 보기·전체 화면 진입/종료·리사이즈에서 기술 노드와 제목이 잘리지 않는지 확인한다. 390px 화면과 모션 감소 설정에서도 확인하고 콘솔 오류를 점검한다.

문서만 수정하거나 소스만 고치고 기존 HTML을 그대로 두면 이미 생성된 페이지에는 반영되지 않는다.
